## Missing or partial, ranked

1. **Permission and ownership editor, including safe recursive application** (rows 49–54, ✗). This is core Linux file-manager functionality: users need to inspect and repair ownership, execute bits and access modes.
2. **Path completion and normal filesystem path handling** (rows 17–22, ✗/◐; location suggestions are `known`). Tab completion, `~`, URI handling and selecting a file from its path are expected when navigating a native filesystem.
3. **Breadcrumb overflow navigation and path-bar entry affordance** (rows 7–10, ✗/◐). Long paths become difficult to navigate when the bar only clips them, and the blank-area edit affordance is absent.
4. **Persistent desktop notices for device writes and unmount/eject progress** (rows 42–43, ◐/✗). Users need an OS-level warning before removing a device whose data is still being written.
5. **Breadcrumb location context actions and new-tab navigation** (rows 3–6, ✗/◐). These avoid re-traversing parent folders and make the location bar behave as a full navigation surface.
6. **Open typed file paths by selecting the file in its parent** (row 21, ◐). Users commonly paste a file path and expect the file manager to reveal that file.
7. **Redo and operation-specific system notifications** (row 44, ◐). One-step undo is useful, but native file managers also communicate and reverse supported operations consistently.
8. **Configurable context-menu order and complete standard actions** (rows 26–41, ✗/◐). Lower priority than direct filesystem access, but customization and action availability matter for mature desktop integration.
9. **Order editor and minor typography fidelity** (rows 45–48, ✗/◐). These improve customization and polish but have lower value than navigation, permissions and device safety.
