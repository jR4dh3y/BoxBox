## Missing or partial, ranked

1. Wallpaper picker validation and format behavior differ: GPUI accepts an unfiltered path prompt, uses a 32 MiB cap and image decoder limits, and does not reproduce the web's 20 MiB/type/error rules; the picker is explicitly untested (`known`).
2. Preview support is narrower than the frontend type classifier: office/notebook preview and some code/dotfile cases are absent (`known`); image zoom and previous/next are also listed as known native gaps in `UI_MAP.md`.
3. The delayed folder-load spinner is absent (`known`), so slow loads do not receive the web's delayed feedback behavior.
4. Native context menus include Open with; the remaining mismatch is remote/read-only menu gating and Preview availability.
5. Frontend virtual scrolling preserves a keyed anchor across item/geometry changes and view teardown; GPUI virtualizes, but its per-pane scroll handles do not provide that same anchor restoration.
6. Single-dotfile extension handling differs, which changes icon/preview classification for names such as `.bashrc`.
7. Native wallpaper palette application omits the web's separately calculated accessible text/icon colors and solid accent contrast treatment.
8. Browser upload/share upload queues, chunk hashing/resume, anonymous-share folder uploads, and their HTTP error mapping have no GPUI implementation; they are web/server flows or are replaced by local native imports/transfers.
9. The public share permission summary uses different wording: native lists literal permissions rather than the web's concise precedence labels.
