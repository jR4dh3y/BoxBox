## Missing or partial, ranked

1. **Trash metadata and ordering differ (◐).** GPUI uses a 64 KiB metadata ceiling vs Go’s 1 MiB; it sorts oldest deletion first rather than directories first/newest mtime, has a 1,024 collision ceiling vs 10,000, and does not revalidate inode identity before destructive trash actions.
2. **Trash restore cannot recreate absent original parents (◐).** Go creates missing parents and re-resolves the mount before no-replace restore; GPUI requires an existing canonical parent.
3. **Directory and transfer limits are absent (◐).** Go rejects listings above 10,000 entries and transfer trees above depth 64 / 10,000 entries; GPUI local listing/copy has no equivalent cap.
4. **GIO volume view/actions are not equivalent to the current UDisks2 implementation (◐).** Fixed data partitions, capability flags, read-only/space details, GIO command errors and post-action confirmation can differ from GPUI’s UDisks-filtered device list.
5. **Shared freedesktop thumbnails are missing (✗, known).** Existing GPUI thumbnails are app-local memory cache only, so other file managers cannot reuse them and GPUI cannot consume their cache.
6. **The xdg document portal picker is missing (✗, known).** The current download prompt does not establish portal chooser semantics or portal grants.
7. **Shift+Delete outside Trash is missing (✗, known).** Local Delete moves to Trash; the native shortcut list documents only Delete and does not provide permanent deletion outside Trash.
8. **Thumbnail worker hardening differs (◐).** The Go path uses a read-only FD, process-group cancellation, 8-second timeout and 1 MiB JPEG ceiling; the Rust call site does not show equivalent bounds.
9. **Drive cards lack backend device/filesystem/mount metadata (◐).** GPUI reports configured-root statvfs values, not the deepest mount’s device, filesystem type and mount point returned by Go.
10. **The saved remote server/profile gateway is deferred (—).** These backend services cover validation, permission-protected credential storage and route forwarding, while the current native map schedules server management/pairing for later.
