## Missing or partial, ranked

1. **System file chooser portal (`✗ known`)**: GPUI has no exported xdg-desktop-portal FileChooser implementation, so other sandboxed applications cannot receive the same file-picker integration or grants.
2. **GIO/UDisks volume parity (`◐`)**: GPUI has live UDisks2 mount/eject, but does not mirror GIO's visible volume metadata, confirmed action state, GVfs MTP/network volumes, or encrypted-volume unlock.
3. **Freedesktop shared thumbnails (`◐ known`)**: current thumbnail path does not establish interoperability with thumbnailers and `~/.cache/thumbnails`, affecting cache reuse and supported file types.
4. **Open With defaults and icon path (`◐`)**: current GPUI supports Open With, but lacks Go's preservation/update of desktop-specific MIME overrides plus confirmation, and GTK themed icon rasterization.
5. **Clipboard edge handling (`◐`)**: core GNOME/URI-list interoperability exists, but the publisher/backend and parser differ in format ownership, validation limits, and cut clearing when another app changes ownership.
6. **Archive portability limits (`◐`)**: native ZIP exists, but Go's 100,000-entry ceiling and deterministic Windows-safe component/collision naming are not shown to match.
7. **Trash identity/safety details (`◐`)**: GPUI implements Trash and restore, but opaque ID collision resistance and metadata handling differ from the Go device/inode/ctime identity checks.
