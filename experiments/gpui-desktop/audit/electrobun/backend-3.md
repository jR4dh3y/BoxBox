## Scope notes

This chunk is backend service code, not the Electrobun frontend or HTTP handlers. Its copy/move/delete jobs, resumable upload sessions, thumbnail endpoint, system-drive scan and account wallpaper storage are server-facing facilities. There is no trash-spec implementation, clipboard MIME negotiation, GIO/UDisks call, or portal picker in these ten files. `job.go`'s delete removes entries permanently. The native GPUI implementation supplies local Trash and clipboard behavior separately; the current UI map identifies the portal picker and shared freedesktop thumbnail cache as still missing (`UI_MAP.md:87–89, 99`).

## Missing or partial, ranked

1. **Shared freedesktop thumbnails — ◐ known.** GPUI renders bounded previews but keeps only its in-process 96-image cache; other desktop apps cannot reuse it.
2. **Portal file picker — ✗ known.** The UI map still lists xdg-desktop-portal selection as unimplemented, so native chooser handoff is absent.
3. **Search and recursive-copy limits — ◐.** Go traversal stops at 100,000 entries; GPUI's corresponding paths can walk more, and search's symlink traversal differs.
4. **Transfer semantics — ◐.** Native local Trash is a desirable replacement for backend permanent deletion, but copy-symlink and local cross-filesystem move behavior differ from Go service semantics.
5. **Job lifecycle contract — ◐.** GPUI shows useful local progress/cancellation, but does not reproduce the server queue cap, owner-scoped snapshots, or retained job history.
6. **Drive inventory — ◐.** GPUI has real UDisks2 mount/eject integration, while backend `df` stats and its container-specific filtering are a separate inventory contract.
7. **Wallpaper validation/storage — ◐.** Both affect only BoxBox's own workspace background, but supported formats, size limits and persistence model differ.
