# BoxBox Red-Team Report — 2026-08-07

**Method:** live attack against a production-mode build (auth, rate limiting, and lockout all enabled) running on `127.0.0.1:18080`, with a hostile mount containing traps (symlink → `/etc/passwd`, HTML/SVG script payloads, quoted filenames). 30+ attacks executed. Every finding from the 2026-07-28 audit was also re-verified against source and live behavior.

Scope: full backend (`backend/internal/**`), frontend auth/preview/upload paths, Dockerfile, docker-compose, `.env.example`, git history.

---

## Executive summary

The July audit findings are **all fixed and verified under live attack**. One new HIGH-severity issue was found (stored XSS via file preview), plus a medium and a set of low/polish items. The auth layer, path-safety layer (including `/proc/self/fd` TOCTOU re-validation), and container hardening are strong.

Verdict: **one real HIGH remains.** Fix the preview sandboxing and the attack surface is thin.

## NEW findings (confirmed live)

### H1 — Stored XSS via file preview (same-origin script execution)

`GET /api/v1/stream/preview/<mount>/<file>` serves user-controlled content **inline, same-origin**:

```
Content-Type: text/html; charset=utf-8        <- evil.html
Content-Type: image/svg+xml                   <- xss.svg (script executes top-level)
Content-Disposition: inline
Content-Security-Policy: object-src 'none'; base-uri 'self'; frame-ancestors 'self'; form-action 'self'
```

The global CSP has **no `script-src`**, so uploaded HTML/SVG files execute JavaScript on the application origin. This defeats the otherwise-solid token design:

- Access token is in JS memory only (not directly readable)
- Refresh token is an HttpOnly cookie (not directly readable)
- **But** the cookie is path-scoped to `/api/v1/auth`, so injected JS mints a fresh token legitimately:

```js
fetch('/api/v1/auth/refresh', { method: 'POST', credentials: 'same-origin' })
  .then(r => r.json())
  .then(d => exfil(d.accessToken)); // SameSite=Strict does not help — request IS same-site
```

`location.href` additionally leaks the 15-minute `?token=` from the preview URL.

**Attack chain:** any user who can upload plants `evil.html` → anyone previews it → attacker receives a working access token → full API access to all mounts.

**Fix:**

```go
// handler/stream.go — Preview() and Download()
w.Header().Set("Content-Security-Policy", "sandbox; default-src 'none'; style-src 'unsafe-inline'")
```

Additionally force `Content-Disposition: attachment` (or `text/plain`) for active MIME types (`text/html`, `image/svg+xml`, `application/xhtml+xml`, `text/xml`), and add `sandbox=""` to the `PdfPreview.svelte` iframe as defense-in-depth. Gold standard long-term: serve previews from a separate throwaway origin.

### M1 — Upload session IDs predictable + not user-scoped

`frontend/src/lib/utils/upload.ts:80`:

```ts
return `upload_${Date.now()}_${Math.random().toString(36).substring(2, 11)}`;
```

Millisecond timestamp + `Math.random()` is enumerable. Sessions live in a global map; `UploadStatus` and `AcceptChunk` never check who created the session. An authenticated attacker enumerates IDs → reads other users' upload **file paths** (info disclosure) or races chunks into a foreign session (integrity/DoS).

**Fix:** `crypto.randomUUID()` on the frontend; server-side, store `claims.Username` at session creation and reject chunk/status calls from any other user.


### L1 — `Content-Disposition` filename quote injection (confirmed live)

File named `evil"name.txt` produces:

```
Content-Disposition: attachment; filename="evil"name.txt"
```

Malformed header, parsed inconsistently across proxies/browsers. The July audit noted "sanitized and quoted" — it is quoted, **not** sanitized. Go blocks CRLF (no response splitting), so impact is low. **Fix:** escape `\`/`"` per RFC 6266 or restrict to `[A-Za-z0-9._-]` and add `filename*=UTF-8''…`.

### L2 — Lockout = silent account DoS

6 failed logins every 15 minutes keeps any account locked out indefinitely; the legitimate user only sees the (intentionally) uniform "Invalid username or password". Keep the uniform error, but **log lockout events** so operators can detect the pattern.

### L3 — `HTTPWriteTimeout = 0` (`config/constants.go:16`)

Slow-reader clients hold connections/goroutines indefinitely; under the 512 MB container limit, an authenticated user can drip-feed downloads into memory exhaustion. Consider a generous write timeout or a minimum byte-rate floor.

### L4 — Unknown `/api/*` routes fall through to the SPA

`GET /api/version` returns `200` + HTML. Confuses API clients and scanners. Add a JSON 404 handler for the `/api` subtree.

### L5 — Misleading error on blocked symlink-escape upload

Upload-over-symlink-escape is correctly blocked, but returns `"Mount point is read-only"` — it is actually an escape block. Mislabeling will confuse incident response.

### L6 — `requestIsHTTPS` trusts `X-Forwarded-Proto` from any peer

`handler/auth.go:188` — not exploitable to weaken cookies (only strengthens), but on plain-HTTP deployments an injected header produces unsendable `Secure` cookies (self-DoS). Gate on `trusted_proxies`.

### L7 — Supply-chain leftovers

GitHub Actions pinned by major tag, not SHA (pin by full SHA); hostile-file parsers (`@e965/xlsx`, `docx-preview`, `pptx-preview`) execute in the token-holding origin — sandbox previews once H1 is fixed.
